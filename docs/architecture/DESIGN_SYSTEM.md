# Akari 设计系统

Akari 是温馨、富媒体、带有二次元色彩的个人博客主题。设计目标不是堆叠装饰，而是让文章、照片、音乐、瞬间和人与人之间的回应处在同一个有生活感的空间里。

本文保留长期设计原则。精确颜色、选择器和组件实现以 `src/styles/` 当前源码为准。

## 视觉性格

核心关键词：晚灯、春日、纸张、胶片、住人的房间、克制的二次元感。

- 温馨来自低对比暖底、留白、柔和阴影和真实内容，不来自大面积粉色。
- 二次元感来自题签、插画、非对称圆角和轻巧动效，不使用廉价霓虹、玻璃拟态堆叠或通用 AI 插画感。
- 富媒体内容必须仍然服从阅读层级；图片、音频和视频不能挤压正文与操作区域。
- 默认资源要像主题的一部分，并允许用户用 Halo 动态内容替换。

## 颜色与字体

明暗模式全部使用 `src/styles/tokens.css` 中的语义令牌。组件不得绕过令牌新增一套平行的页面色板；确需固定色的媒体遮罩，应同时检查文字对比度。

- 明亮模式：暖米色画布、接近纸张的表面、深褐墨色、莓果强调色。
- 深色模式：紫褐夜色画布、暖白文字、降低饱和度的强调色。
- 正文使用系统中文无衬线字体栈，标题使用宋体/明朝体方向的展示字体栈。
- 展示标题允许紧凑字距；正文保持舒展行高和自然换行，不依赖强制断字塑造版面。

用户配置的强调色是源令牌，悬停、阴影和深色模式色值应由语义令牌派生，不能假设任意输入色都能直接充当文字颜色。

## 布局与尺寸依据

- 桌面内容壳最大宽度约 1200px，左右保留至少 20px 安全边距；移动端进一步收紧但不贴边。
- 主要按钮最小高度 48px，图标按钮和导航操作区不小于 44×44px，依据可触达性而非视觉图形本身。
- 正文行长优先保证阅读舒适，侧栏、TOC 和媒体说明不能侵占正文主列。
- 24px 左右的大圆角用于 Hero 和主要媒体面；12–18px 用于控制面、纸条和普通卡片；小折角只用于表达纸张语义。
- 同一层级使用稳定间距节奏。元素变多时先调整布局或换行，不压缩到失去呼吸感。

具体断点和尺寸由对应 `pages/*.css`、`shared/responsive.css` 与 UnoCSS shortcut 决定。文档不维护一份会与代码漂移的像素抄本。

## 信息层级

页面通常遵循以下顺序：

1. 眉题或类别提示；
2. 明确的页面标题；
3. 一句解释当前空间用途的副标题；
4. 主要内容；
5. 补充入口、统计或回应。

不要为了填满版面添加与 Halo 数据无关的虚构文案。空状态应说明当前缺少什么、如何补充，并保持与正常状态相同的空间气质。

## 图标

- 默认使用 Lucide 的 Iconify 图标，保持同一套笔画语言。
- 正文内联图标通常为 16–18px，导航为 18–21px，强调图标可到 24–28px。
- 点击热区由按钮尺寸承担，不能把图标本身放大到填满热区。
- 同一图标在页面内保持同一语义；装饰图标不得获得误导性的按钮样式。
- 后台可配置菜单图标由 Halo Iconify 字段提供，不手写未经处理的 SVG。

## 图片与媒体

- 封面裁切必须围绕内容主体设置 `object-position`，不能只依赖统一居中。
- 卡片图片应有明确宽高或比例，避免加载时布局跳动。
- 图片上文字必须配合渐变遮罩，且在最亮、最暗两类图片上都可读。
- 图片失败时显示与主题一致的兜底资源或文字首字，不显示破损图标。
- 灯箱按钮固定在安全屏幕边缘，描述拥有独立可见区域，不随大图溢出屏幕。
- 播放器需要真实媒体状态、时长、进度、错误和空列表状态。

## 动效

动效表达空间关系和操作反馈，不作为装饰层叠加。

- 页面切换：内容连续过渡，持久播放器不重建；当前页面回顶使用平滑滚动。
- 内容入场：以轻微位移和透明度为主，避免首帧先显示再隐藏造成闪烁。
- 卡片悬停：优先改变阴影、遮罩和 1%–3% 的媒体景深，不让大卡片无缘由弹跳。
- 操作反馈：按钮按压幅度克制，状态切换必须与用户动作同时发生。
- 同一元素的同一 `transform` 只能由一个动效系统控制，避免页面入场和悬停互相覆盖。
- 常规反馈使用 160–320ms；媒体景深和较大空间变化可使用 400–620ms。严肃阅读界面避免明显回弹。
- 优先动画 `transform` 与 `opacity`；避免持续动画布局属性或滥用 `will-change`。
- `prefers-reduced-motion` 或主题安静模式下，保留结果状态，取消非必要位移、缩放和自动旋转。

## 组件原则

- Header：品牌、主导航和工具顺序稳定；“更多”由菜单元数据决定，不在模板写死。
- 卡片：整张卡片可点击时不要嵌套第二个竞争链接；标题、元信息和标签有稳定层级。
- 筛选器：激活项不改变原始顺序；局部更新不触发整页闪烁，并保留 URL 可分享性。
- 评论：头像、名字、时间、正文和回复关系清晰；提交状态、失败重试与权限提示可见。
- TOC：层级缩进可辨识、纵向可滚动、无横向滚动条，定位需考虑粘性 Header 偏移。
- 分页/加载更多：使用真实下一页数据，追加内容后保持焦点、滚动位置和终止状态。

## 响应式与无障碍

- 先保证窄屏阅读与触控，再扩展桌面布局；不能仅通过缩小桌面版完成移动适配。
- 所有交互元素支持键盘和清晰的 `:focus-visible`。
- 图标按钮提供可读名称；装饰图片使用空 `alt`，内容图片提供与上下文一致的替代文本。
- 颜色不能作为唯一状态信号；文字、图标或结构需要共同表达。
- 模态框和灯箱管理焦点、Escape 关闭和背景滚动。
- 长标题、长标签、长评论和无封面数据必须作为常规状态验证。

## 修改前后的设计检查

1. 这项变化是否服务内容或操作，而不是单纯增加效果？
2. 尺寸是否来自可读性、可触达性、层级或媒体比例？
3. 浅色与深色的文字、边框和遮罩是否都清晰？
4. 桌面、移动、键盘和减少动效状态是否完整？
5. 动态 Halo 数据变长、为空或加载失败时，结构是否仍成立？
6. 是否复用了现有令牌与组件语言，而非创造局部风格？

只有当前实现确实需要长期约束时才更新本文。一次性的像素对比和问题截图应留在任务上下文或 Git 历史中，不进入设计系统。
